## Proposed decisions

- **PD-IMP-214-1 (501 exception name):** card step 1 names a `NotImplementedYet` domain error. IMP-103 already built `EndpointNotImplemented` (501, `NOT_IMPLEMENTED`) in `app/core/errors.py`, and every stub reuses it. No second class was added. Proposed: align the card text.
- **PD-IMP-214-2 (API-01 shape):** §6.6.1 gives `HealthOut` as `{status, version, provider}`, but the merged API-01 (IMP-103) also returns `environment`. That is an added field, which §6.1 allows in v1, so it was kept unchanged. Proposed: list `environment` in §6.6.1.
- **PD-IMP-214-3 (ApiError fields):** card step 3 names `{code, message, request_id, details}`. §7.1 names `{status, code, message, details, requestId, retryAfterS}`. §7.1 was built because it covers the card's fields. Proposed: align the card.
- **PD-IMP-214-4 (base URL):** `.env.example` sets `NEXT_PUBLIC_API_BASE_URL=http://localhost:8000/api/v1`, while the contract paths already start with `/api/v1`. The client strips a trailing `/api/v1` (`apiOrigin`), so either form works and the variable is unchanged. Proposed: say in §4.5 that the value may include `/api/v1`.
